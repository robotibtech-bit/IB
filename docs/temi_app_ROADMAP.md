# 테미 도서관 안내 앱 제작 가이드라인 및 Claude AI 단계별 로드맵

## 1. 문서 목적

이 문서는 `테미 도서관.pdf`의 화면·운영 요구사항을 빠짐없이 앱 요구사항으로 변환하고, Claude AI에게 0단계부터 순서대로 개발을 지시하기 위한 실행 가이드다.

대상은 도서관에 배치되는 13.3인치 Temi 로봇용 Android 앱이다. 특정 도서관 전용으로 고정하지 않고, 관리자가 도서관명과 운영 콘텐츠를 직접 입력하여 여러 도서관에서 재사용할 수 있게 만든다. 이용자는 큰 버튼과 짧은 문장으로 시설 안내, 도서관 이용방법, 어린이 콘텐츠, 행사 안내를 이용한다.

## 2. 개발 전 확정 원칙

### 2.1 필수 원칙

- PDF에 제시된 기능과 화면 흐름을 모두 포함한다.
- PDF의 `신트리도서관` 명칭과 시설명은 화면 구성 예시일 뿐 고정값으로 사용하지 않는다.
- 도서관명은 최초 설정 또는 관리자 화면에서 직접 입력·수정하며 앱 전체에 즉시 반영한다.
- 모든 하위 화면의 상단 앱 바에 `뒤로가기`와 `홈` 버튼을 항상 표시한다.
- 메인 화면에는 홈 버튼이 불필요하므로 앱 이름 또는 도서관 이름만 표시할 수 있다.
- 13.3인치 가로 화면을 우선 지원하고, 큰 버튼·큰 글씨·짧은 문장을 적용한다.
- 어린이와 고령층이 설명 없이도 사용할 수 있어야 한다.
- 시설 목록은 앱에 고정하지 않고 실제 Temi에 등록된 POI를 불러와 자동 구성한다.
- 관리자는 Temi에서 불러온 각 POI에 표시명, 층, 설명, 안내 방식, 아이콘과 노출 여부를 추가 설정할 수 있다.
- 같은 층 목적지는 Temi가 직접 동행하고, 다른 층 목적지는 층·이동 방향·엘리베이터 위치를 안내하도록 POI별로 설정할 수 있다.
- 도서관 운영정보와 콘텐츠는 코드에 고정하지 않고 관리자 설정 또는 로컬 데이터 파일에서 변경 가능하게 설계한다.
- 로봇 SDK 연결 전에도 일반 Android 태블릿/에뮬레이터에서 전체 UI와 흐름을 시험할 수 있어야 한다.

> **정정 (2026-08-04):** 위 "도서관명은 최초 설정 또는 관리자 화면에서 직접 입력·수정" 원칙을
> 정정한다. 도서관명은 **"신트리도서관"으로 고정**하며, 최초 설정 화면(`initial_setup`)은 두지
> 않는다. 이 문서의 3.1/4.1/10장/추적표에서 도서관명 관리자 입력·수정을 언급하는 부분은 모두
> 이 정정을 따른다(문단 전체를 다시 쓰지 않고 이 정정 노트로 대체).

### 2.2 권장 기술 기준

- Android Studio 최신 안정 버전
- Kotlin
- Jetpack Compose + Material 3
- 단일 Activity + Navigation Compose
- MVVM 또는 단순화된 Clean Architecture
- Kotlin Coroutines / StateFlow
- Hilt(프로젝트 규모가 작다면 수동 DI도 가능)
- Room: 운영정보, 퀴즈, 추천도서, 행사, 이용 통계
- DataStore: 앱 설정, 무입력 시간, 음성 사용 여부, 관리자 설정
- Temi SDK는 `RobotService` 인터페이스 뒤에 격리
- `FakeRobotService`와 `TemiRobotService`를 분리하여 개발·현장 환경을 전환

### 2.3 PDF 기반 디자인 원칙

- PDF의 전체 인상인 흰색 배경, 민트·청록 포인트 색상, 짙은 남색 제목, 둥근 카드와 넉넉한 여백을 따른다.
- 메인 화면은 PDF처럼 도서관명과 짧은 환영 문구를 위쪽에 두고 핵심 목적 버튼을 큰 카드로 제공한다.
- 시설 선택 화면은 PDF처럼 아이콘이 있는 큰 목적지 카드를 사용한다.
- 주요 기능은 `메뉴 선택 → 세부 항목 선택 → 결과·안내`의 3단계 구조가 시각적으로 드러나게 한다.
- 선택 버튼은 민트색 채움, 일반 버튼은 흰색 바탕과 민트색 또는 연회색 테두리를 기본으로 한다.
- 이용방법과 어린이 콘텐츠의 단계 제목에는 PDF의 파란색 제목 바 표현을 참고하되 전체 민트 테마와 어울리게 통일한다.
- 어린이 콘텐츠에는 부드러운 파스텔 색상과 친근한 아이콘을 사용할 수 있지만 공통 상단바·글꼴·모서리 규칙은 유지한다.
- PDF 이미지를 그대로 복제하지 않고 13.3인치 화면의 가독성과 실제 터치 동작에 맞게 재구성한다.

> Claude는 실제 프로젝트의 기존 Gradle, Kotlin, Compose, Temi SDK 버전을 먼저 확인하고 호환되는 버전만 사용해야 한다. 확인 없이 라이브러리 버전을 임의 변경하지 않는다.

## 3. PDF 기반 전체 요구사항

### 3.1 메인 화면

표시 요소:

- 도서관명: 관리자가 입력한 명칭
- 환영 문구: `안녕하세요. 무엇을 도와드릴까요?`
- `시설을 찾고 있어요`
- `이용방법이 궁금해요`
- `로봇과 놀아요`
- `오늘의 행사`

동작:

- 네 개 항목은 각각 해당 첫 화면으로 이동한다.
- 한 화면에 복잡한 기능을 나열하지 않고 방문 목적 중심으로 구성한다.
- 도서관명을 아직 설정하지 않았다면 이용자 화면을 열기 전에 최초 설정 화면으로 이동한다.
- 관리자에서 도서관명을 수정하면 앱 재설치나 코드 수정 없이 메인과 관련 안내 문구에 즉시 반영한다.

### 3.2 시설 안내

3단계 흐름:

1. 메인에서 `시설을 찾고 있어요` 선택
2. 주요 장소를 큰 버튼으로 선택
3. 목적지와 층에 맞는 안내 방식 제공

PDF에 제시된 장소 예시:

- 1층 어린이자료실
- 1층 무인반납실
- 1층 안내데스크
- 1층 엘리베이터
- 2층 디지털자료실
- 2층 열람실
- 3층 종합자료실
- 4층 강의실

위 장소들은 고정 요구사항이나 초기 하드코딩 목록이 아니다. 실제 시설 안내 목록은 Temi에 현재 등록된 POI를 기준으로 생성한다.

장소 선택 화면:

- Temi SDK에서 조회한 전체 POI 중 관리자가 `이용자에게 노출`로 설정한 POI
- `다른 장소 찾기`
- POI가 많을 경우 검색 및 전체 목록 보기
- Temi에서 POI가 추가·이름 변경·삭제되면 동기화 후 목록에 반영

안내 방식:

- 1층 목적지: `동행 안내`, `위치만 보기`
- 타 층 목적지: 해당 층과 위치, 엘리베이터까지의 이동 방법 및 방향 안내
- 예시 문구: `어린이자료실은 1층입니다. 함께 이동해 안내해드릴게요.`
- 현재 위치와 직접 동행 가능 여부는 관리자 설정으로 결정한다.
- 신규 POI는 `미설정` 상태로 표시하고, 관리자가 층과 안내 방식을 입력하기 전에는 이용자 화면에서 숨기거나 Temi 직접 동행만 제공한다.

동행 안내 상태:

- 이동 시작 전 목적지 확인
- 이동 중 목적지, 진행 상태, `이동 중지` 표시
- 도착 시 도착 음성/화면 안내
- 이동 실패 시 재시도, 위치만 보기, 홈으로 이동 제공

### 3.3 도서관 이용방법 안내

3단계 흐름:

1. 이용방법 메뉴 선택
2. 세부 항목 선택
3. 핵심 답변 제공

1차 메뉴:

- 책 대출·반납
- 회원가입
- 열람실 이용
- 운영시간·휴관일

`책 대출·반납` 세부 항목:

- 대출 가능 권수
- 대출 기간
- 연장·예약
- 무인반납 방법

정보 제공 원칙:

- 답변은 핵심 내용 3줄 이내를 우선한다.
- 필요한 경우 QR코드를 제공한다.
- 관련 시설 위치 안내로 연결한다.
- 상세 문의는 `직원 도움`으로 연결한다.
- 예시 답변: `도서는 회원증으로 대출할 수 있습니다. 대출 기간과 권수는 자료 유형에 따라 다릅니다. 자세한 내용은 안내데스크에 문의해 주세요.`
- 답변 화면에는 `무인반납실 안내`, `직원 도움` 등 관련 행동 버튼을 배치한다.

### 3.4 어린이 콘텐츠

3단계 흐름:

1. 어린이 콘텐츠 메뉴 선택
2. 세부 콘텐츠 선택
3. 결과 표시 및 다음 행동 유도

콘텐츠 메뉴:

- 오늘의 퀴즈
- 나에게 맞는 책 / 추천도서
- 도서관 예절
- 행사 연계

오늘의 퀴즈:

- 주제 예시: 동물, 공룡, 과학, 동화
- 한 번에 최대 3문제
- 보기 3개
- 선택 즉시 짧은 음성 및 화면 피드백
- 정답/오답 결과 표시
- 결과 화면에서 추천도서 노출
- `어린이자료실 안내`
- `다른 퀴즈 하기`

추천도서:

- 연령별 또는 주제별 추천
- 표지, 제목, 저자, 한 줄 소개, 자료실/청구기호 또는 위치정보 표시
- 어린이자료실 안내로 연결

도서관 예절:

- 짧은 카드 또는 퀴즈 형태
- PDF의 예시처럼 `도서관에서 책을 다 읽은 뒤 책 수레에 놓아 주세요`와 같이 행동 중심으로 안내

### 3.5 오늘의 행사·프로그램 및 공지

- 오늘의 행사
- 행사 신청 또는 안내 QR
- 장소 안내
- 주요 공지
- 행사명, 시간, 장소, 대상, 짧은 설명, 신청 여부를 표시
- 행사가 없으면 빈 화면이 아니라 `오늘 예정된 행사가 없습니다`와 다음 행사 또는 홈 버튼을 제공

### 3.6 공통 상단 바와 내비게이션

모든 하위 화면:

- 왼쪽: 뒤로가기
- 가운데: 현재 화면 제목
- 오른쪽: 홈
- 아이콘과 `뒤로`, `홈` 텍스트를 함께 표시하여 고령층도 이해하게 한다.

예외 및 기준:

- 뒤로가기는 직전 논리 화면으로 이동한다.
- 홈은 어디서든 메인으로 이동하며 중복 화면 스택을 제거한다.
- 로봇 이동 중 홈/뒤로를 누르면 `안내 이동을 중지하고 이동하시겠습니까?` 확인창을 표시한다.
- Android 시스템 뒤로가기도 앱의 뒤로가기와 동일하게 동작한다.

### 3.7 음성 안내

- 주요 화면 진입, 선택 결과, 이동 시작·도착, 퀴즈 정오답을 짧게 읽어준다.
- 도서관 환경을 고려해 음량을 관리자 설정으로 조절한다.
- 동일 문구가 중첩 재생되지 않도록 이전 발화를 취소하거나 큐 정책을 명시한다.
- 음성 실패가 화면 조작을 막지 않아야 한다.

### 3.8 접근성·화면 기준

- 13.3인치 가로 화면 기준
- 최소 터치 영역 64dp 권장
- 본문 22sp 이상, 주요 버튼 26sp 이상 권장
- 텍스트와 배경 대비를 충분히 확보
- 색만으로 상태를 구분하지 않고 아이콘·텍스트 병행
- 버튼 라벨은 짧고 일관되게 작성
- 연속 터치 방지
- TalkBack 의미 라벨 제공
- 네트워크가 없어도 핵심 시설·이용정보와 기본 퀴즈는 동작

## 4. 추가하면 실제 운영에 유용한 기능

PDF 목적을 벗어나지 않으면서 운영에 직접 필요한 항목만 포함한다.

### 4.1 관리자 설정

- 관리자 비밀번호 진입
- 도서관명과 환영 문구 직접 입력·수정
- Temi POI 새로고침 및 동기화
- Temi에서 조회된 POI의 원본명, 이용자용 표시명, 층, 설명, 안내 방식, 아이콘, 노출 여부
- 신규·변경·삭제된 POI 상태 표시
- 운영시간·휴관일
- 대출·반납, 회원가입, 열람실 정보
- 퀴즈, 추천도서, 행사·공지
- QR 링크
- 음량과 무입력 홈 복귀 시간
- 콘텐츠 노출/숨김 및 순서
- 데이터 내보내기/가져오기(JSON)

### 4.2 무입력 자동 복귀

- 일정 시간 입력이 없으면 메인으로 복귀
- 일반 화면과 결과 화면에 적용
- 로봇 이동 중에는 자동 복귀하지 않음
- 충전 상태일 경우에는 자동 복귀하지 않음
- 관리자에서 시간 변경 가능

### 4.3 이용 통계

개인정보 없이 다음 이벤트만 집계:

- 메뉴별 선택 횟수
- 시설별 안내 요청 수
- 동행 안내/위치만 보기 횟수
- 이동 성공·중지·실패
- 이용방법 항목별 조회
- 퀴즈 시작·완료·정답률
- 추천도서 조회
- 행사 조회·QR 열기
- 직원 도움 요청

### 4.4 안전·오류 대응

- Temi SDK 미연결
- 로봇 위치 미확인
- 잘못된/없는 POI
- 이동 요청 거절 또는 실패
- 네트워크 끊김
- 콘텐츠 없음
- QR 링크 오류

각 오류는 기술 코드 대신 이용자에게 할 수 있는 다음 행동을 보여준다.

## 7. 로봇 연동 인터페이스

```kotlin
interface RobotService {
    val connectionState: StateFlow<RobotConnectionState>
    val navigationState: StateFlow<NavigationState>

    suspend fun speak(text: String)
    suspend fun stopSpeaking()
    suspend fun goTo(poiName: String): Result<Unit>
    suspend fun stopNavigation(): Result<Unit>
    suspend fun getKnownPois(): Result<List<String>>
}
```

구현체:

- `FakeRobotService`: 에뮬레이터/일반 태블릿용. 일정 시간 뒤 이동 성공·실패를 재현한다.
- `TemiRobotService`: 실제 Temi SDK 콜백을 `StateFlow`로 변환한다.

주의:

- UI나 ViewModel에서 Temi SDK 객체를 직접 호출하지 않는다.
- Temi SDK 연결 상태와 이동 상태를 단일 상태 머신으로 관리한다.
- 화면이 사라져도 이동 콜백이 중복 등록되지 않게 한다.
- 이동 명령에는 이용자용 표시명이 아니라 Temi에서 조회한 원본 `sourcePoiName`을 사용한다.
- 앱 시작 및 관리자 새로고침 시 `getKnownPois()` 결과와 로컬 시설 설정을 동기화한다.
- 새 POI는 자동 추가하되 기본값은 `미설정`으로 두고 기존 POI의 관리자 메타데이터를 덮어쓰지 않는다.
- Temi에서 사라진 POI는 로컬에서 즉시 삭제하지 않고 `Temi에서 찾을 수 없음`으로 표시하여 관리자가 확인하게 한다.

## 14. 최종 완료 기준

- PDF에 제시된 시설 안내, 이용방법, 어린이 콘텐츠, 행사 안내가 모두 작동한다.
- 도서관명은 관리자 화면에서 자유롭게 입력·수정할 수 있고 즉시 반영된다.
- 시설 목록은 특정 명칭으로 고정되지 않고 Temi에 등록된 POI를 동적으로 반영한다.
- PDF의 흰색·민트 기반 색상, 큰 카드, 짧은 문장, 명확한 3단계 흐름이 일관되게 적용된다.
- 1층 목적지는 동행, 타 층 목적지는 위치 안내가 정확히 분기된다.
- 모든 하위 화면에서 뒤로가기와 홈이 일관되게 작동한다.
- 이동 중 뒤로/홈/중지가 안전하게 처리된다.
- 관리자 변경이 앱에 정상 반영된다.
- 네트워크 또는 Temi SDK 장애 시 앱 전체가 멈추지 않는다.
- 핵심 안내는 오프라인에서도 제공된다.
- 어린이와 고령층이 3단계 이내에 주요 목적을 달성한다.
- 실제 Temi POI와 앱의 시설 데이터가 동기화되고 관리자 메타데이터가 안전하게 유지된다.
- 장시간 반복 사용 및 현장 인수 시나리오를 통과한다.
