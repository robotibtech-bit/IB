# 실시간 좌석 · 예약현황 메뉴 추가 작업 명세

## 1. 작업 목적

현재 도서관 앱의 홈 화면에서 사용자가 **디지털자료실 예약현황과 열람실 좌석현황을 빠르게 확인할 수 있도록 독립 메뉴를 추가**한다.

기존 `이용안내` 내부에 포함되어 있던 `실시간 좌석현황` 기능은 새 메뉴로 이동한다.

이번 작업에서는 **현황 조회 기능까지만 구현**한다.

실제 좌석/PC를 예약하는 기능 또는 예약 사이트 연결 기능은 추후 검토 후 추가한다.

---

# 2. 홈 화면 변경

## 현재

홈 화면 하단에 `행사 안내` 버튼이 전체 폭을 사용하고 있다.

## 변경

현재 `행사 안내` 버튼의 가로 크기를 약 절반으로 줄인다.

남은 공간에 새로운 버튼을 추가한다.

### 왼쪽

`행사 안내`

### 오른쪽

`실시간 좌석 · 예약현황`

두 버튼이 같은 행에 나란히 배치되도록 한다.

기존 홈 화면 전체 디자인 스타일, 여백, 라운드, 색상, 아이콘 스타일 등을 최대한 유지한다.

새 버튼을 추가하기 위해 다른 홈 메뉴의 크기나 전체 레이아웃을 불필요하게 변경하지 않는다.

---

# 3. 신규 메뉴

홈 화면의

`실시간 좌석 · 예약현황`

버튼을 누르면 새로운 화면으로 이동한다.

화면 제목:

# 실시간 좌석 · 예약현황

이 화면에는 두 개의 큰 선택 카드를 배치한다.

---

## 카드 1

### 디지털자료실 예약현황

설명:

`PC 및 디지털자료실 이용 현황을 확인해요.`

버튼 또는 카드 선택 시 아래 URL을 연다.

http://digital8.ice.go.kr:8800/LibMate/LibMate.php

가능하면 앱에서 사용 중인 기존 웹페이지 표시 방식이 있다면 동일한 방식을 재사용한다.

새로운 WebView 구조를 중복해서 만들기 전에 기존 구현을 확인한다.

---

## 카드 2

### 열람실 좌석현황

설명:

`열람실의 실시간 좌석 이용 현황을 확인해요.`

이 기능은 새로 만드는 기능이 아니다.

현재 앱의

`이용안내 → 실시간 좌석현황`

에 연결되어 있는 기존 기능을 그대로 이동한다.

기존에 사용 중인 URL, WebView 처리, 로딩 처리 등의 로직을 최대한 재사용한다.

---

# 4. 기존 이용안내 메뉴 수정

현재:

`이용안내 → 실시간 좌석현황`

버튼이 존재한다.

이 버튼은 삭제한다.

단, **연결되어 있던 실제 좌석현황 기능이나 관련 코드를 무조건 삭제하면 안 된다.**

기존 기능을 새로 만든

`홈 → 실시간 좌석 · 예약현황 → 열람실 좌석현황`

에서 사용할 수 있도록 이동/재사용한다.

즉,

기존 메뉴 진입점만 제거하고 기능은 새 위치로 옮긴다.

---

# 5. 화면 흐름

최종적인 기본 화면 흐름은 다음과 같다.

```text
홈
│
├─ 기존 메뉴들
│
├─ 행사 안내
│
└─ 실시간 좌석 · 예약현황
       │
       ├─ 디지털자료실 예약현황
       │      └─ LibMate 현황 페이지
       │
       └─ 열람실 좌석현황
              └─ 기존 실시간 좌석현황 페이지
```

---

# 6. 추후 확장을 고려한 구조

현재는 구현하지 않지만 추후 다음 기능을 추가할 가능성이 있다.

```text
디지털자료실 예약현황
       │
       ├─ 현황 보기
       └─ 예약하러 가기

열람실 좌석현황
       │
       ├─ 현황 보기
       └─ 예약하러 가기
```

따라서 신규 화면이나 navigation 구조를 만들 때 향후 `예약하러 가기` 기능을 추가하기 어렵게 하드코딩하지 않는다.

다만 이번 작업에서는 실제 예약 URL이나 예약 기능이 확인되지 않았으므로 **예약 버튼을 임의로 만들지 않는다.**

---

# 7. UX 제안

`실시간 좌석 · 예약현황` 화면에서는 일반적인 작은 메뉴 버튼보다 큰 카드 형태를 권장한다.

예:

```text
┌──────────────────────────────────┐
│  💻  디지털자료실 예약현황       │
│                                  │
│  PC 및 디지털자료실 이용         │
│  현황을 확인해요.                │
│                           〉      │
└──────────────────────────────────┘


┌──────────────────────────────────┐
│  🪑  열람실 좌석현황             │
│                                  │
│  열람실의 실시간 좌석 이용       │
│  현황을 확인해요.                │
│                           〉      │
└──────────────────────────────────┘
```

실제 구현에서는 Emoji를 그대로 사용하라는 의미가 아니다.

현재 앱에서 사용하고 있는 Material Icon 또는 기존 이미지 에셋 스타일에 맞는 아이콘을 사용한다.

---

# 8. WebView 관련 권장사항

외부 현황 페이지를 표시할 때 기존 앱에 WebView 공통 화면이 있다면 우선 재사용한다.

다음 사용자 편의 기능도 기존 구현 여부를 확인한다.

- 로딩 중 표시
- 웹페이지 로딩 실패 안내
- 다시 시도
- 앱 화면으로 돌아가기
- Android 뒤로가기 처리
- 웹페이지 내부 이동 후 뒤로가기 처리

단, 기존 구조를 대규모로 변경하면서까지 추가하지 않는다.

---

# 9. 중요 작업 원칙

이번 작업의 핵심은 **새 기능 추가 + 기존 기능 이동**이다.

다음 사항을 반드시 지킨다.

1. 기존 `행사 안내` 기능을 삭제하거나 변경하지 않는다.
2. 행사 안내 버튼은 기능은 유지하고 크기/배치만 조정한다.
3. 기존 `열람실 실시간 좌석현황` 기능을 삭제하지 않는다.
4. 기존 이용안내에서는 해당 메뉴의 진입 버튼만 제거한다.
5. 기존 열람실 좌석현황 기능을 신규 화면에서 재사용한다.
6. LibMate 주소는 아래 주소를 사용한다.

`http://digital8.ice.go.kr:8800/LibMate/LibMate.php`

7. 임의의 예약 URL을 추측해서 추가하지 않는다.
8. 이번 단계에서는 실제 예약 기능을 구현하지 않는다.
9. 기존 정상 동작 중인 다른 메뉴와 navigation을 건드리지 않는다.
10. 기존 앱의 디자인 시스템을 최대한 유지한다.

---

# 10. 구현 전 확인

바로 코드를 작성하기 전에 프로젝트를 분석하여 다음을 먼저 확인한다.

- HomeScreen 구조
- 행사 안내 버튼 구현 위치
- 이용안내 메뉴 구조
- 기존 `실시간 좌석현황` 버튼 위치
- 기존 좌석현황 URL
- 기존 WebView 구현 방식
- Navigation 구조
- 뒤로가기 처리 방식

분석 후 기존 구조를 최대한 재사용하여 최소 수정으로 구현한다.
